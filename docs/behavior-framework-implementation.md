## Corrected contracts

- The host boundary owns semantic input actions through their existing verified completion. Reads, tick waits, checkpoints and safety configuration are not discretionary boundaries. Operator origin is separate from a manually started standalone script.
- MCP `script_action` queues a cooperative button on an existing standalone coroutine; it does not create a direct await. Preserve that run's policy. REPL/direct awaits, including phase entry, are plain unless `humanize = true` is explicit.
- When P3 separates policies, plain execution must retain route/safety policies from the declared activity while disabling discretionary breaks/releases and choosing a natural mouse. The temporary enum-only plain context is replaced with those field overrides.
- Every pending action and attempt has cancellation identity; stale callbacks cannot touch replacements. Emergency recovery and physical takeover remain independent of discretionary policy and intent scopes.
- Menu target resolution already follows beforeAction. Removing the pre-action long-break path must preserve post-login readiness, instead of assuming all settling was stale-target repair.
- Micro pressure accumulates against one sampled budget. Do not repeatedly resample the cumulative probability at each boundary. Test equal active time across dense and sparse boundary schedules.
- The standalone script's activity determines the micro rate even while a REPL command is busy. Skilling, questing and combat use the full profile rate; general activity uses 80% and travel uses 60%. Manual and operator-only time contribute nothing. A boundary may delay a due break; starting that break consumes all pressure instead of queuing several breaks from one delayed boundary. State v3 persists pressure and the next budget, and migrates older states with zero pressure. A sufficiently long long break clears micro pressure along with the existing one-boundary suppression.
- Micro-break cursor release is selected only after the break starts. Independent travel glances belong to the cursor model and require another minute of owned active time. Rest cleanup cancels its own scope; it cannot cancel a separately owned break or explicit offscreen action.
- A resumed via walk carries explicit passed-via progress tied to the original request constraints. Reissuing an unqualified new journey starts a new journey. Via progress is observed execution progress, not simply membership in a planned route.
- Continuation tokens bind the account, destination, arrival radius and ordered via list. Avoid tiles and interrupt conditions are refreshed from current observations on each resumed request. Tokens are single-use and bounded to the last 64 interrupted journeys in this client process; unknown, changed or replayed tokens are rejected explicitly.
- Click reach must stop at the next unpassed via point. Otherwise the game's own minimap pathfinding can cut across a safe corridor even when the host's planned polyline includes it. The handoff radius permits continuous progress without creating another await boundary.
- The temple trapdoor list contains alternative arrival tiles, as shown by its occupied-tile skip and early return once any approach reaches the trapdoor. Preserve that allowed set through optional `arrival_tiles`, while corridor points remain `via`. Its audit starts at the caller's prayer-switch threshold; starting at the first arrival candidate would prove only an already-arrived case.
- A route array's first point can itself be a safety waypoint, rather than the player's start. An offline plan from `prison_clear` (2762,2804) to Garkor crosses five prison tiles without constraints. Preserve the northern Garkor corridor and the initial authored points of other explicit corridors; audit their actual caller starts. Continuations preserve observed progress, while a fresh request starts a fresh journey.
- Stamina upkeep with an energy threshold requires both an inactive effect and low energy. Refresh its interrupt condition after each receipt: wait for effect expiry while active, then for the energy threshold while inactive. This preserves the existing potion handler and avoids re-interrupting forever on a condition that handler intentionally leaves unchanged.
- Constrained corridor routes are audited with their via requirements. Their unconstrained shortest paths in the original review are comparison metrics, not valid upper bounds for a safer constrained route.
- Interrupts precede arrival, rejoin and input dispatch, and cancel all pending walk-owned input before returning. Handlers for prison/capture/supplies remain in Lua.
- Interrupt priority is area, dialogue, poison, missing names, inventory minimums, skill minimums, varbit equality, then run energy. Energy thresholds use percent, while raw player energy remains hundredths of a percent. Missing snapshot data returns `unavailable`, preserving a continuation instead of pretending supplies are absent.
- The dungeon's existing upkeep also requires a food reserve, prayer points and an active stamina effect. Generic `inventory_below = {{id = ..., quantity = ...}}`, `skill_below = {prayer = ...}` and `varbit_equals = {{id = ..., value = ...}}` predicates preserve these checks without teaching the walker quest or potion decisions. Numeric-id predicates use row arrays so Lua's array/map normalization cannot confuse ids 0 or 1.
- Normal route clicks use a profile-derived cadence (usual gaps 2-6 seconds, occasional longer gaps). Reaching an accepted target does not trigger another click early, and a deliberate pause there does not count as a stall. Near clicks sample 60-90% of the currently projectable route reach, preserving the via cap. Additional profile values use new labels in the existing copula and survive unrelated manual overrides.
- Edge memory is keyed by the account-hash-derived profile and stored under `navigation/edges-<profile>.json`. Locked feedback lasts four hours; solid edges and exhausted/rejected interactions last five minutes. Every plan captures current memory, and a queued result is rejected if its memory changed. Failed door entries also clear when the captured quest enum or numeric main stage changes. The existing ten-tick refresh interval bounds that delay; unsupported stages and auxiliary access flags are not inferred. Cleared outcomes last one day as evidence and never override collision.
- Walk receipts include `edge_memory` observations with reason, object/action, detail, observation/expiry times and quest sensitivity. Arrival past an interacted obstacle also records its cleared outcome. Only game/spam messages containing the whole word `locked` establish that reason; player chat, `blocked` and `unlocked` do not. Account changes cancel old travel and invalidate snapshots/continuations. A failed navigation load cannot reuse old knowledge or prevent other account owners from activating.
- Transport planning must use an admissible heuristic for its edge costs; a geometric heuristic alone is invalid for cheap long-distance transports. Performance changes require measurements and must preserve routes needing large detours.
- Expected damage changes discretionary policy only; it does not disable forced healing or emergency escape. An unavailable snapshot never becomes safe state.
- Area rectangles and corridor points come from Lua. No hazardous travel is validated without the user watching. Do not create video or JSONL gameplay recordings.
